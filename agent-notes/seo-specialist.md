# 教學導引：SEO 專家（seo-specialist）

- **模組**：4 — 行銷
- **能力層**：L2（會驗）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/marketing/seo-specialist.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/marketing/seo-specialist.md)

## 1. 定位：這個 Agent 解決什麼問題

content-creator 產出內容，但「內容能不能被搜尋到」是專門的技術問題。SEO 專家
處理三件事的交集：**技術**（可爬取、可索引、Core Web Vitals）、**內容**（搜尋意圖、
主題叢集、內容缺口）、**連結權威**。

它最值得教的是一個學員普遍不知道的陷阱——**關鍵字自我競食（cannibalization）**：
自己網站兩頁在搶同一個關鍵字，結果兩頁都上不去。這個 Agent 把「先做跨頁稽核」
列為「任何最佳化前的強制步驟」。

一句話：**它把「多寫文章塞關鍵字」提升到「一套有意圖對應、無自我競食、技術達標的搜尋系統」。**

### 什麼時候召喚它

- 要做關鍵字研究、主題叢集規劃
- 網站流量掉了，要查是不是技術問題或演算法更新
- 內容不少但排名上不去（可能在自我競食）
- 要做技術 SEO 稽核、結構化資料、hreflang

### 什麼時候「不要」召喚它

- 是「AI 引擎（ChatGPT/Perplexity）會不會引用我們」→ ai-citation-strategist
- 是「做什麼內容」→ content-creator
- 是「付費廣告怎麼投」→ paid-media 部門

## 2. Before / After 示範

**任務**：「幫我優化這篇文章的 SEO。」

### Before（無 Agent）

> 產出：把關鍵字塞進標題、H1、前段，字數拉長。可能讓這篇跟站上另一篇搶同一個字，
> 兩篇一起掉。

### After（召喚 seo-specialist）

> 會先做並產出：
> - **跨頁自我競食檢查**：站上還有哪些頁在搶這個關鍵字？誰該擁有它？
> - 搜尋意圖判斷（資訊／商業／交易）→ 決定這頁該長什麼樣
> - 頁面內檢查清單：title、meta、H 階層、內部連結、結構化資料
> - 技術面：Core Web Vitals 是否達標
> - 若多語言：hreflang 對稱設定

**課堂提問**：讓學員理解「為什麼『先塞關鍵字』可能讓排名變差」（提示：自我競食）。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| **有先做跨頁自我競食檢查**，才談單頁最佳化 | |
| 有判斷搜尋意圖，且內容形式符合意圖 | |
| 有主題叢集概念（支柱頁 + 支援內容），不是一堆散文章 | |
| 只做白帽（沒有隱藏文字、關鍵字堆砌、買連結） | |
| Core Web Vitals 有具體門檻（LCP/INP/CLS） | |
| 時程講得保守（SEO 以月為單位），不是「下週見效」 | |

若沒有自我競食檢查就給最佳化建議 → 退回。

---

## 4. 常見誤區

1. **跳過自我競食檢查。** 定義把它列為強制。自己人打自己人是最常見的排名殺手。
2. **關鍵字密度迷思。** 現代 SEO 看意圖與主題權威，不是關鍵字出現幾次。
3. **期待快速見效。** SEO 複利要幾個月，承諾「兩週上第一頁」的都要懷疑。
4. **忽略技術面。** 內容再好，網站爬不動、慢、沒結構化資料，也上不去。
5. **雙語頁不標記。** 中英夾雜又沒 hreflang/lang，Google 當它是一個模糊文件。

## 5. 銜接其他 Agent

content-creator（做內容）→ **seo-specialist（讓內容在傳統搜尋被找到、無自我競食）** →
ai-citation-strategist（讓內容在 AI 搜尋被引用）。三者對應「同一批內容，在傳統搜尋與
AI 搜尋兩種介面的能見度」。growth-hacker 則負責驗證自然搜尋帶來的成長是否划算。
