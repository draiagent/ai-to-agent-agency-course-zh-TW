# Lab：MCP 建構者（mcp-builder）

- **模組**：18　**能力層**：L3→L4　**建議時間**：30 分鐘（課堂）＋ 作業延伸
- **前置**：已安裝 `mcp-builder.md`。想一個「你希望 agent 能做、但目前做不到」的動作
  （查某系統的資料、觸發某流程、讀某檔案…）。

---

## 練習 1：先設計介面（L3）

1. 對 mcp-builder 說出你的需求，要求它**先產出介面**：工具名、描述、參數 schema，
   還沒有任何實作。
2. 檢查：工具名是 verb_noun 嗎？描述有講「何時該用」嗎？每個參數有型別、預設、描述嗎？
3. 把最糟的一個工具名（例如 `getData`）挑出來，要求改成無歧義的。

**評分要點**
- ✅ 介面先行、命名無歧義、描述講「何時用」
- ❌ 工具叫 `query`、參數是一個字串 → 追問：agent 怎麼知道該傳什麼？

---

## 練習 2：一職責一工具（L3）

1. 給 Agent 一個「一個工具做太多事」的設計（例：`manage_user`，帶 `action` 參數：get/update/delete）。
2. 要求它拆成多個單一職責工具，並說明為什麼。
3. 討論：從 agent 的角度，「一個工具帶 mode」和「三個清楚的工具」，哪個比較不會呼叫錯？

**評分要點**：學員理解「每個工具一個職責」讓 agent 更容易挑對。

---

## 練習 3：優雅失敗 + agent 測試（L3→L4）

1. 要求 mcp-builder 為工具加上錯誤處理：API 掛掉、憑證無效、速率限制、空結果各回什麼。
2. 檢查：錯誤是回 `isError: true` + 可行動訊息，還是丟 stack trace / 讓伺服器崩？
3. 紙上推演一次完整迴圈：agent 讀描述 → 挑這個工具 → 送參數 → 拿到錯誤 → 它會怎麼做？

**評分要點**：學員理解「錯誤要讓 agent 知道『重試還是問使用者』，而不是幻想一個回應」。

---

## 繳交

- 練習 1 的工具介面設計（名稱 + 描述 + 參數 schema）
- 練習 2 的「一職責一工具」拆分
- 練習 3 的錯誤處理設計 + 完整迴圈推演 + 150 字內反思：
  修完這門課，你最想幫你的 AI 助理「造」哪一個它現在還沒有的工具
