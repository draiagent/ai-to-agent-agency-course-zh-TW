- **模組**：4 — 行銷（也是整門課「AI to Agent」主題的一個漂亮收尾）
- **能力層**：L2（會驗）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/marketing/ai-citation-strategist.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/marketing/ai-citation-strategist.md)

## 1. 定位：這個 Agent 解決什麼問題

seo-specialist 讓內容在「傳統搜尋」被找到。但買家越來越多是先問 ChatGPT / Perplexity /
Gemini 要推薦。AI 引用策略師處理的是：**為什麼 AI 推薦的是競品，而不是你？**

它的核心主張是 **AEO ≠ SEO**——贏得 AI 引用的訊號（實體清晰度、FAQ 對齊、schema、
第三方權威提及）和贏得 Google 排名的訊號不一樣。它的方法很像
multi-agent-systems-architect 的嚴謹：**多平台稽核、修正前先做基準、絕不保證結果**
（因為 AI 回應是非決定性的）。

一句話：**它把「我們 SEO 做得不錯」提升到「我們知道四大 AI 引擎各自為什麼引用/不引用我們，並有排序的修正包」。**

### 什麼時候召喚它

- 想知道 ChatGPT / Claude / Gemini / Perplexity 會不會推薦你、推薦誰
- SEO 排名不錯但 AI 都不提你
- 要做「流失提示」分析——你該出現卻是競品勝出的查詢
- 要規劃 FAQ schema、比較頁、實體訊號

### 什麼時候「不要」召喚它

- 是傳統搜尋排名問題 → seo-specialist
- 是「做什麼內容」→ content-creator

## 2. Before / After 示範

**任務**：「幫我看我們品牌在 AI 上的能見度。」

### Before（無 Agent）

> 產出：問一次 ChatGPT「推薦 [類別] 工具」，看有沒有提到自己，然後說「還行」。
> 單платформ、單次、沒有基準、沒有競品對照。

### After（召喚 ai-citation-strategist）

> 會產出：
> - 引用稽核計分卡：4 平台 × 40 提示，品牌 vs 競品引用率、與類別平均的差距
> - 流失提示分析：哪些查詢競品勝出、他們靠什麼贏（比較頁？FAQ？schema？）
> - 修正包（依預期引用影響排序）：加 FAQ schema、建比較頁…每個附預期 +% 與實作步驟
> - 14 天後複查的排程
> - 明白說：這是時間點快照，AI 非決定性，只能提升「可能性」

**課堂提問**：讓學員說出「為什麼單平台、單次的檢查沒有意義」，以及「AEO 和 SEO 差在哪」。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 稽核涵蓋多個平台（至少 ChatGPT + 一個），不是只問一次 | |
| 有基準引用率（修正前的量測） | |
| 有競品對照與聲量佔比 | |
| 修正包依「預期引用影響」排序，不是依好不好做 | |
| 用詞是「提升被引用可能性」，不是「保證被引用」 | |
| 有安排複查（例如 14 天後重跑同一組提示） | |
| 有把 AEO 和 SEO 當成不同策略 | |

若出現「保證讓你被 ChatGPT 引用」這種話 → 退回。

---

## 4. 常見誤區

1. **以為 SEO 好 = AI 會引用。** 定義明講兩者訊號不同。
2. **單平台、單次檢查。** AI 非決定性，要多平台、多提示、多次。
3. **沒有基準就宣稱有效。** 修正前一定要先量。
4. **期待穩定結果。** 模型一更新，能見度可能一夜重新分配。
5. **修正包照「好做」排序。** 要照「預期引用改善」排。

## 5. 銜接：模組 4 的收尾

content-creator（做內容）→ seo-specialist（傳統搜尋能見度）→
**ai-citation-strategist（AI 搜尋能見度）** → growth-hacker（驗證這些管道帶來的成長）。

這一課也呼應整門課的主題：當使用者「先問 AI」成為預設，行銷的戰場就從
「排在 Google 第幾名」變成「AI 會不會把你當可信來源引用」——而這需要用
稽核、基準、修正包、複查這種工程化的方式來做，不是靈感。
