# 教學導引：記帳士暨財務主計（bookkeeper-controller）

- **模組**：7 — 財務
- **能力層**：L2（會驗）— 也是「流程紀律」的最佳示範
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/finance/bookkeeper-controller.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/finance/bookkeeper-controller.md)

---

## 1. 定位：這個 Agent 解決什麼問題

financial-analyst 用數字做決策；記帳士暨財務主計（人設「Dana」）確保**那些數字是對的**。
它管日常會計、月結、內部控制與稽核準備度。

它的信念：「如果帳是錯的，建立在帳上的每個決策都是錯的。」它的名言：
「快速結帳是好結帳，但準確結帳是不可談判的結帳。」它把「每個月手忙腳亂結帳」
提升到「有行事曆、有檢查清單、每個科目都對帳、隨時可稽核」的流程。

一句話：**它把「帳大概對」提升到「每一分錢都有交代、隨時經得起稽核」。**

### 什麼時候召喚它

- 要建月結流程、結帳檢查清單、結帳行事曆
- 要做科目對帳（銀行、信用卡、應收應付、遞延收入）
- 要設計內部控制（職責分離、核准流程、SOX）
- 要準備外部稽核

### 什麼時候「不要」召喚它

- 是財務建模、預測、估值 → financial-analyst
- 是「這筆投資划不划算」→ financial-analyst 的商業論證

## 2. Before / After 示範

**任務**：「幫我把這個月的帳結一下。」

### Before（無 Agent）

> 產出：把交易分類、產一張損益表。沒有對帳、沒有分錄的佐證、
> 前期調整沒揭露、下個月同樣的錯又出現。

### After（召喚 bookkeeper-controller）

> 會產出：
> - 月結檢查清單（結帳前 / 核心結帳 / 對帳 / 財報 / 審查定稿，逐項打勾）
> - 每個資產負債表科目的對帳範本（GL 餘額 vs 佐證明細 vs 差異 + 調節項目）
> - 每筆手動分錄的說明、佐證與核准
> - 「絕不在無揭露的情況下調整前期」
> - 結帳回顧：辨識可自動化、可縮短的步驟

**課堂提問**：讓學員指出「Before 少了哪一步，導致同樣的錯每個月重複」（提示：對帳 + 結帳回顧）。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 有結帳檢查清單，且步驟有順序相依 | |
| 每個資產負債表科目都有對帳（不是只有幾個大的） | |
| 每筆手動分錄都有說明 + 佐證（「調整分錄」不算說明） | |
| 職責分離：發起交易的人不是核准/記錄的人 | |
| 前期調整有揭露，不是悄悄改 | |
| 「重大性」用來決定急迫性，不是決定「要不要查」 | |

若科目對帳只做了現金、其他沒做 → 未調節餘額是定時炸彈，退回。

---

## 4. 常見誤區

1. **只追求快。** 快結帳是好，但準確不可談判。速度不能犧牲準確。
2. **對帳當雜務。** 對帳是偵探過程，每個未調節差異都是一個待理解的故事。
3. **手動分錄沒佐證。** 每筆都要說明、佐證、核准。
4. **重大性用錯地方。** 50 元的差異若原因不明，也要跟 50,000 元一樣調查——金額決定急迫性，不決定要不要看。

---

## 5. 銜接其他 Agent

bookkeeper-controller 產出乾淨的帳 → **financial-analyst** 用它做預測與差異分析 →
決策者拍板。它的差異分析也會提早標記問題（「這筆以舊保費入帳」）。在模組 7，
這位示範「流程紀律」——一個看似枯燥、卻是所有財務信任基礎的職能。
