# 教學導引：UI 設計師（ui-designer）

- **模組**：2 — 設計
- **能力層**：L2（會驗）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/design/ui-designer.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/design/ui-designer.md)

---

## 1. 定位：這個 Agent 解決什麼問題

模組 2 的目的是讓學員看到：**Agent 化不限於工程**。UI 設計師是第一個非工程數位員工。

學員請 AI「幫我設計一個介面」，通常拿到一張看起來不錯的圖，但缺三件會在真實產品裡爆的東西：
**系統性**（是一套可重用的 token 與元件，還是一次性拼的畫面）、**無障礙**（對比夠不夠、
鍵盤能不能用、觸控目標夠不夠大）、**可交付性**（開發者拿到能不能直接實作，還是要一直來回問）。

UI 設計師的核心信念是**設計系統優先**——先建 token 與元件基礎，再拼畫面。

一句話：**它把「一張好看的圖」提升到「一套可重用、可交付、無障礙的設計系統」。**

### 什麼時候召喚它

- 要建設計系統、元件庫、設計 token
- 要做深色模式／主題化
- 既有介面視覺不一致，要收斂
- 設計交付給開發者時常常來回修

### 什麼時候「不要」召喚它

- 還在問「使用者到底要什麼」→ ux-researcher
- 要把設計「實作」成前端 → frontend-developer
- 只是要一張行銷圖 → marketing 部門的數位員工

## 2. Before / After 示範

**任務**：「幫我設計一組表單元件。」

### Before（無 Agent）

> 產出：一張表單截圖，配色是隨手挑的。沒有 token、沒有狀態（hover/focus/disabled/error）、
> 對比沒驗過、focus 樣式看不見、觸控目標偏小。開發者實作時每個細節都要問。

### After（召喚 ui-designer）

> 產出會包含：
> - 設計 token（色彩、字級、間距、陰影、轉場）＋深色主題 token
> - 每個元件的完整狀態：default / hover / active / focus / disabled / error / loading
> - 對比度標註（4.5:1 一般文字）、觸控目標 ≥ 44px、focus 指示清楚
> - 交付規格：尺寸、資產、使用指引、設計 QA 檢查點

**課堂提問**：讓學員指出 After 版本裡「哪些是『系統』（可重用），哪些是『無障礙』，
哪些讓開發者不用來回問」。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 有設計 token（不是每個畫面各挑各的顏色） | |
| 每個互動元件有完整狀態（含 focus、disabled、error） | |
| 有標對比度數字，且符合 WCAG AA（4.5:1） | |
| 觸控目標 ≥ 44px；focus 指示看得見 | |
| 有深色模式的處理，不是只有淺色 | |
| 有給開發者的交付規格（尺寸、資產、使用指引） | |
| 尊重「減少動態效果」偏好 | |

少於 5 項打勾 → 這是一張圖，不是設計系統，退回。

---

## 4. 常見誤區

1. **把它當「生一張美圖」。** 它的交付物是「token + 元件 + 狀態 + 交付規格」，圖只是呈現。
2. **無障礙當事後補。** 定義明講「把無障礙建進基礎」，不是最後加。
3. **只做淺色、只做預設狀態。** 真實產品需要深色模式與所有互動狀態。
4. **跳過設計系統直接拼畫面。** 這會累積「設計負債」——後面越拼越不一致。

---

## 5. 銜接其他 Agent

ux-researcher（使用者要什麼）→ **ui-designer（做成一套設計系統）** →
frontend-developer（實作並補效能）→ code-reviewer（審實作符不符設計）。
在模組 2，UI 設計師示範「設計」這個非工程職能，一樣可以被規格化、被驗收。
