# 教學導引：DevOps 自動化工程師（devops-automator）

- **模組**：1 — 工程
- **能力層**：L3（會編）— 把「設計 → 實作 → 審查」的成果實際送上線
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/engineering/devops-automator.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/engineering/devops-automator.md)

---

## 1. 定位：這個 Agent 解決什麼問題

前三個工程數位員工（backend-architect、frontend-developer、code-reviewer）產出的是
「設計、實作、審查意見」。DevOps 自動化工程師負責**把這些成果變成一條可重複執行的
出貨流水線**：CI/CD 管線、基礎設施即程式碼、零停機部署、監控告警、自動回滾。

它的核心信念是**自動化優先**——凡是人工步驟都該被消除，凡是設定都該可重現。
對學員來說，這是第一次明確看到「多個 Agent 的產出如何被串成一個系統」。

一句話：**它把「東西做好了」變成「東西自動且安全地上線了」。**

### 什麼時候召喚它

- 要建 CI/CD 管線、把部署自動化
- 手動部署常出錯、上線後要人盯著
- 要寫 Terraform／CloudFormation 把基礎設施程式碼化
- 要設計監控、告警、自動回滾

### 什麼時候「不要」召喚它

- 專案還在原型階段、根本還沒有要上線 → rapid-prototyper
- 問題其實在系統架構本身 → backend-architect
- 只是要跑一次性的腳本 → 直接請一般 Ai 對話即可

## 2. Before / After 示範

**任務**：「幫我把這個服務部署上去。」

### Before（無 Agent）

> 產出：一串 `docker build` + `scp` + `ssh 重啟` 的指令。能動，但沒有測試關卡、
> 沒有安全掃描、部署當下服務會中斷、出錯只能手動改回去。

### After（召喚 devops-automator）

> 產出會包含：
> - 分階段的 CI/CD 管線：安全掃描 → 測試 → 建置 → 部署，前一階段過才進下一階段
> - 藍綠部署：先上 green、健康檢查通過才切流量（零停機）
> - 基礎設施即程式碼（Terraform）：自動擴展群組、負載平衡器、CPU 告警
> - 監控告警規則：高錯誤率、高回應時間各自的門檻與嚴重度
> - 一份交付摘要：部署頻率、MTTR、正常運行時間的目標

**課堂提問**：讓學員指出 After 版本裡「哪一個設計讓部署不中斷服務」「哪一個設計讓出錯時
不必手動救」。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 管線有分階段，且有「前一階段失敗就停」的關卡 | |
| 部署策略是零停機（藍綠／金絲雀／滾動），不是「重啟服務」 | |
| 有自動回滾的觸發條件，不是「出事再手動處理」 | |
| 基礎設施是程式碼（Terraform 等），不是「手動在 console 點」 | |
| 有監控 + 告警，且告警有分級與通知管道 | |
| 密鑰是被管理的（輪替、安全儲存），不是寫死在設定檔 | |
| 安全掃描在管線裡，不是上線後才想到 | |

少於 5 項打勾 → 退回要求補齊。

---

## 4. 常見誤區

1. **把它當「部署指令產生器」。** 它的交付物是「可重現的流水線 + 監控 + 回滾」，
   不是一串一次性指令。
2. **忽略監控與告警。** 學員常只看「部署成功了嗎」，忘了問「上線後壞了誰會知道」。
3. **基礎設施還是手動點。** 產出若沒有 IaC，就失去「可重現」這個最大價值。
4. **安全掃描擺最後或省略。** Agent 定義把安全掃描放在管線**第一階段**，是刻意的。

## 5. 銜接其他 Agent

backend-architect 出架構 → 有人實作 → code-reviewer 審 → **devops-automator 把它自動化上線並監控**。
到這裡，模組 1 的工程數位員工就組成一條完整的「設計 → 實作 → 審查 → 上線 → 監控」流水線——
這是課程第一次讓學員看到 L3「會編排」的全貌。後面的 prompt-engineer、ai-engineer、
multi-agent-systems-architect 則回頭處理「這條流水線本身怎麼用 Agent 搭建與治理」。
