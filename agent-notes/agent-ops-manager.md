# 教學導引：數位員工長（agent-ops-manager）

- **模組**：18 — 跨域專業（治理席位）
- **能力層**：L3→L4（會編 → 會養）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/specialized/agent-ops-manager.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/specialized/agent-ops-manager.md)（🆕 本 repo 原創，非上游衍生）

---

## 1. 定位：這個 Agent 解決什麼問題

前 17 個模組都在教「怎麼用好某一個數位員工」。這一課反過來問：**當你同時養了十幾個
agent，誰在管這一群？** 誰有權限碰什麼、誰改過設定、這個月花了多少 token、出事怎麼回滾。

數位員工長就是這個治理席位。它不做任何業務任務，它管的是團隊本身：登錄與版本、
最小權限、稽核軌跡、成本歸屬、事故回滾、新增／修改／退役的關卡。

它的核心紀律：**每個 agent 有真人擁有者**、**預設零權限、逐項核准**、
**每個副作用動作留稽核軌跡**、**高風險動作要真人按確認**、**出事先止血再究責**、
**效率不能換取略過監督**。

一句話：**它把「我們有一堆好用的 agent」提升到「這群 agent 誰負責、能碰什麼、留了什麼軌跡、出事怎麼辦，都寫清楚了」。**

這一課是整門課「L4 會養」的正式落點——把散在各角色的「依回饋調整、沉澱成資產」收斂成一個席位。

### 什麼時候召喚它

- 團隊要開始同時營運 3 個以上 agent
- 要盤點現有 agent 的權限、擁有者、成本
- 要設計 agent 上線前的驗收關卡、事故回滾程序
- agent 產出過錯誤／越權的東西，要做根因分析

### 什麼時候「不要」召喚它

- 要它幫忙做某個業務任務 → 找對應的專業角色；它治理團隊，不搶團隊的活
- 是把多個 agent 串成一條業務流程 → `multi-agent-systems-architect`（它管拓撲與交接，數位員工長管治理與權限）
- 是資安入侵事件本身 → `security/` 的角色

## 2. Before / After 示範

**任務**：「我們想再加一個會自動回客訴信的 agent，今天就上。」

### Before（無此角色）

> 產出：直接把 agent 接上信箱，給它寄信權限，開始跑。三天後它對一位客戶承諾了
> 一筆未經授權的退款，沒人知道它還對誰講過什麼。

### After（召喚 agent-ops-manager）

> 會產出：
> - 登錄表一列：擁有者（客服主管）、用途、風險分級（高——可對外送出、涉及金錢承諾）
> - 權限：可讀客訴信、可草擬回信；**寄出與任何退款承諾需真人核准**
> - 稽核軌跡：每封草稿的輸入、輸出、是否被核准、寄給誰
> - 上線判定：可進「試行」，前兩週所有外送信人工過目
> - 回滾方式：出問題就凍結，回到「只草擬不寄出」的版本

**課堂提問**：讓學員指出 Before 的三個缺口（沒有擁有者、權限過大、沒有稽核軌跡），
以及「今天就上」該被換成什麼條件。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 每個 agent 都有一位指名的真人擁有者 | |
| 權限是「預設全禁、逐項開啟」，不是「先全開再說」 | |
| 高風險動作（金流／對外發佈／刪除／法遵）標了「需真人核准」 | |
| 每個副作用動作的稽核軌跡欄位定義清楚（誰／何時／輸入／輸出／影響／是否核准） | |
| 有回滾方式：出事能凍結並回到已知良好版本 | |
| 事故程序是「先止血、再無指責根因分析」，不是先找戰犯 | |
| 有定期複審排程，會收回不再需要的權限 | |

若出現「先上線、權限全開、之後再補治理」→ 退回。

---

## 4. 常見誤區

1. **把它當成又一個做事的 agent。** 它的產出是治理框架，不是業務交付物。
2. **權限先全開。** 最小權限的意思是預設零，不是「先給再收」。
3. **只在出事後才想到回滾。** 回滾方式要在上線前就定義好。
4. **事故檢討變成追責大會。** 無指責根因分析問的是「流程哪裡讓這件事發生」。
5. **用「比較快」正當化略過驗收。** 這正是這個席位存在的理由。

## 5. 銜接其他 Agent

`multi-agent-systems-architect`（設計 agent 之間的拓撲與交接）→ **agent-ops-manager
（治理這群 agent 的權限、成本、稽核、事故）**。它與 `appsec-engineer`（威脅建模、
把檢查變關卡）、`bookkeeper-controller`（職責分離、稽核軌跡）方法同源。
在治理層面，它管的是「數位勞動力」，與 `business-continuity-planner`（管實體與流程的中斷）
共同構成組織的營運韌性。
