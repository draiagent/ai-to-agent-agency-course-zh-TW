# 教學導引：滲透測試員（penetration-tester）

- **模組**：9 — 安全
- **能力層**：L2→L4（會驗 → 會養）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/security/penetration-tester.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/security/penetration-tester.md)

> ⚠️ **教學前提**：這是**攻擊性安全**角色，只用於**經授權**的測試（滲透測試委任、
> CTF、資安研究、防禦用途）。Agent 定義本身內建了強制的授權規則
> （「未經授權的存取是犯罪，不是滲透測試」）。課堂 Lab 一律在
> 刻意架設的靶機、CTF 環境或紙上推演進行，**絕不對真實、未授權的系統操作**。

---

## 1. 定位：這個 Agent 解決什麼問題

appsec-engineer 從防守方看程式碼；滲透測試員**像對手一樣思考、但為防守方工作**。
它的價值是證明「我們從沒被駭過」往往只是「我們從沒注意到」。

它的方法論奠基於公開標準（PTES、OWASP Testing Guide、MITRE ATT&CK、NIST SP 800-115）：
偵察 → 攻擊面測繪 → 利用與後利用 → 文件與報告。它的鐵律：**每個發現都要有
「從初步存取到業務影響」的完整攻擊鏈**——孤立的弱點沒有脈絡就是雜訊。

一句話：**它把「掃描器列了一堆 CVE」提升到「一條可重現、有業務影響的攻擊鏈 + 補救計畫」。**

### 什麼時候召喚它（在授權範圍內）

- 有一份滲透測試委任，要規劃範圍與交戰規則
- 要把零散弱點串成攻擊鏈以展現真實影響
- 要做偵察與攻擊面列舉的方法論
- 要寫「另一位測試員能照著重現」的報告

### 什麼時候「不要」召喚它

- 沒有書面授權——那不是本課程的範圍
- 是防守方的程式碼審查 → appsec-engineer

## 2. Before / After 示範（授權靶機情境）

**任務**：「幫我測這個內部應用的安全。」

### Before（無 Agent）

> 產出：跑一個掃描器、貼一份 200 條 CVE 的清單。沒有哪個能實際利用、
> 沒有攻擊鏈、沒有業務影響、沒有優先序。

### After（召喚 penetration-tester）

> 會產出：
> - 範圍與交戰規則：IP 範圍、測試時段、禁止觸碰的系統、緊急聯絡人
> - 偵察方法論（被動 OSINT → 主動列舉 → 攻擊面測繪）
> - 每個發現的完整攻擊鏈：初步存取 → 升權 → 橫向移動 → 目標
> - 依「嚴重度 + 業務影響」分類，不只看 CVSS
> - 具體補救 + 重測驗證計畫

**課堂提問**：讓學員理解「10 條 medium 弱點串起來 = domain 淪陷」——為什麼攻擊鏈比單一 CVE 分數重要。

---

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 有明確的範圍與書面授權確認（沒有就不能測） | |
| 每個發現都有「從初步存取到業務影響」的完整攻擊鏈 | |
| 發現可從報告單獨重現（另一人能照步驟走） | |
| 依業務影響分類，不只 CVSS 分數 | |
| 每個發現配具體補救（「修補弱點」不是建議） | |
| 有重測驗證計畫 | |

若只是掃描器輸出、沒有手動驗證與攻擊鏈 → 那不算發現，退回。

---

## 4. 常見誤區

1. **掃描器輸出當發現。** 沒有手動驗證的掃描結果不算數。
2. **孤立弱點沒脈絡。** 每個發現都要串成攻擊鏈、連到業務影響。
3. **超出範圍。** 未授權存取是犯罪。永遠先確認書面授權。
4. **補救寫「請修補」。** 要具體：換受管理服務帳戶、輪替密鑰、加分段…

---

## 5. 銜接其他 Agent

penetration-tester 找到攻擊鏈 → **appsec-engineer** 從程式碼層修 → devops-automator
把對應的偵測與防護加進管線 → 重測驗證。在模組 9，攻擊方與防守方兩個角色合起來，
示範「安全是持續的攻防循環」——這也是 L4「會養、能治理」的體現。
