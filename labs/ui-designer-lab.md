# Lab：UI 設計師（ui-designer）

- **模組**：2　**能力層**：L2　**建議時間**：25 分鐘（課堂）＋ 作業延伸
- **前置**：已安裝 `ui-designer.md`。準備一個小介面需求（登入表單／設定頁／卡片列表）。

---

## 練習 1：token 先行（L2）

1. 給 ui-designer 你的介面需求，要求它**先產出設計 token**（色彩、字級、間距、陰影），
   再用這些 token 描述元件。
2. 檢查：元件的每個數值是不是都引用 token，而不是散落的硬編碼值？
3. 追問：「深色模式的 token 呢？」

**評分要點**
- ✅ 先有 token，元件才引用；有深色主題 token
- ❌ 直接給一張畫面、顏色寫死 → 追問：換品牌色要改幾個地方？

---

## 練習 2：狀態與無障礙盤點（L2）

1. 挑一個互動元件（按鈕或輸入框），要求 ui-designer 列出它的**所有狀態**
   （default / hover / active / focus / disabled / error / loading）。
2. 要求每個狀態標：對比度、focus 是否可見、觸控目標尺寸。
3. 對照 `agent-notes/ui-designer.md` 檢核表打勾。

**評分要點**：學員能指出「哪個狀態被漏掉」「哪個對比不足」——用數字驗，不用眼睛。

---

## 練習 3：交付給開發者（L2→L3）

1. 拿練習 1+2 的產出，要求 ui-designer 整理成一份**開發交付規格**。
2. 把這份規格交給 frontend-developer（模組 1），請它指出「這份規格還缺什麼才能直接實作」。
3. 觀察兩個數位員工的產出能不能對接。

**評分要點**：學員能說出「設計交付規格缺了什麼，導致開發還要回頭問設計」——
這是 L2 驗收與 L3 編排的交界。

---

## 繳交

- 練習 1 的設計 token + 引用 token 的元件描述（含深色）
- 練習 2 的元件狀態盤點表（含對比／focus／觸控尺寸）
- 練習 3 的開發交付規格 + frontend-developer 的缺口清單 + 100 字內反思
