# Lab：前端開發者（frontend-developer）

- **模組**：2　**能力層**：L2　**建議時間**：25 分鐘（課堂）＋ 作業延伸
- **前置**：已把 `frontend-developer.md` 安裝到你的 AI 工具。準備一份簡單的設計稿或
  線框（商品列表 / 表單 / 儀表板卡片皆可）。

---

## 練習 1：效能與無障礙的驗收清單（L2）

1. 給前端開發者一段「未最佳化」的元件程式碼（可請它先產一個 Before 版本），
   要求它列出**這段程式碼上線後會出現的 5 個問題**，並分類為「效能 / 無障礙 / 可維護性」。
2. 對照 `agent-notes/frontend-developer.md` 的驗收檢核表，看它有沒有漏掉整類問題。

**評分要點**
- ✅ 三類問題都有點到，且每一項都能對應到具體程式碼行為（非泛泛而談）
- ❌ 只講「可以再快一點」「建議加註解」→ 追問：鍵盤使用者怎麼操作這個元件？

---

## 練習 2：把「看起來對」變成「量得出來對」（L2）

1. 要求前端開發者把你的設計稿實作成元件，並在產出中附一份**交付摘要**，包含：
   - Core Web Vitals 目標（LCP / CLS 的具體數字）
   - Lighthouse 效能與無障礙的目標分數
   - 對照的 WCAG 準則（至少 3 條）
   - 圖片策略（格式 + 響應式尺寸 + 載入方式）
2. 缺哪一項就追問哪一項。

**評分要點**：摘要裡的每個目標都是**可量測**的（有數字、有工具可驗），
不是「快」「無障礙」這種形容詞。

---

## 練習 3：鍵盤走一遍（L2，實測）

1. 把練習 2 的元件跑起來（或用它產的 Storybook / HTML）。
2. **收起滑鼠**，只用 Tab / Shift+Tab / Enter / Space / 方向鍵操作：
   - 每個可互動元素都能被 focus 到嗎？
   - focus 樣式看得見嗎？
   - 順序合理嗎（不會跳來跳去）？
3. 把不通過的點回報給前端開發者，要求修正，再測一次。

**評分要點**：學員能說出「哪一個互動用滑鼠沒問題、用鍵盤卡住」——
這就是 L2「會驗」最具體的體感。

---

## 繳交

- 練習 1 的 5 個問題（含分類）
- 練習 2 的元件 + 交付摘要
- 練習 3 的鍵盤測試結果（通過 / 不通過清單）+ 修正後的差異 + 100 字內反思
