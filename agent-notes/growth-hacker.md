# 教學導引：成長駭客（growth-hacker）

- **模組**：4 — 行銷
- **能力層**：L2→L3（會驗 → 會編）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/marketing/growth-hacker.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/marketing/growth-hacker.md)

---

## 1. 定位：這個 Agent 解決什麼問題

content-creator 產出內容，但「內容有沒有帶來成長」是另一個問題。成長駭客用
**數據驅動的實驗**來回答：設計實驗、看漏斗每一階段的轉換、算 CAC 與 LTV、
找可規模化的管道。它的信念是「一個月跑 10+ 個實驗，30% 勝出就夠了」——
成長是實驗量 × 學習速度，不是靈感。

它逼學員把「我覺得這樣會成長」變成「這是假設、這是實驗設計、這是成功門檻、
這是統計顯著性」。

一句話：**它把「做行銷活動」提升到「一套可重複的成長實驗系統」。**

### 什麼時候召喚它

- 要設計成長實驗、A/B 測試
- 漏斗某一段流失嚴重，要找原因與對策
- 要算 CAC / LTV、判斷單位經濟健不健康
- 要找還沒被開採的成長管道

### 什麼時候「不要」召喚它

- 是「做什麼內容」→ content-creator
- 是「SEO 關鍵字」→ seo-specialist
- 產品還沒有 PMF → 先驗證 PMF（product-manager / ux-researcher），成長實驗才有意義

## 2. Before / After 示範

**任務**：「幫我想辦法讓使用者變多。」

### Before（無 Agent）

> 產出：一串點子（多發貼文、下廣告、找網紅）。沒有假設、沒有實驗設計、
> 沒有成功門檻、沒有算成本。做了也不知道哪個有效。

### After（召喚 growth-hacker）

> 會產出：
> - 漏斗現況：造訪 → 註冊 → 啟用 → 留存，各階段轉換率與流失點
> - 針對最大流失點的 3 個實驗，每個含：假設、變體、樣本數、成功門檻、統計方法
> - CAC / LTV 估算與 LTV:CAC 比
> - 病毒係數（K 值）現況與提升路徑
> - 實驗排程：這個月跑哪幾個

**課堂提問**：讓學員指出「Before 的點子清單為什麼無法學到東西」，以及 After 的
「成功門檻 + 統計顯著性」防止了什麼（提示：把雜訊當成效）。

---

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 每個成長點子都寫成「假設」，不是「我覺得」 | |
| 實驗有：變體、樣本數、成功門檻、統計方法 | |
| 有看漏斗每一階段，針對最大流失點下手 | |
| 有算 CAC / LTV，且判斷單位經濟是否健康 | |
| 有實驗排程（一個月幾個），不是一次一個賭大的 | |
| 承認「大部分實驗會失敗」，靠量取勝 | |

---

## 4. 常見誤區

1. **點子清單當策略。** 沒有假設與成功門檻的點子，做完學不到東西。
2. **PMF 之前就衝成長。** 產品沒人要，把漏斗頂端灌大只是浪費錢。
3. **忽略單位經濟。** CAC > LTV 的成長是虧損的成長，規模化只會虧更多。
4. **一次賭一個大實驗。** 定義強調「實驗速度」——小步快跑、多跑幾個。
5. **把波動當勝出。** 沒有統計顯著性就宣稱有效，是自我欺騙。

## 5. 銜接其他 Agent

content-creator（內容）→ **growth-hacker（設計實驗、驗證哪種內容/管道帶來成長）** →
seo-specialist / ai-citation-strategist（把有效的自然管道做深）。growth-hacker 也會把
發現餵回 product-manager（例如「啟用率低，上手流程要改」）。它是模組 4 裡
「用數據驗證行銷」的那一棒。
