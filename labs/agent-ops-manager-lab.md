# Lab：數位員工長（agent-ops-manager）

- **模組**：18　**能力層**：L3→L4　**建議時間**：30 分鐘（課堂）＋ 作業延伸
- **前置**：已安裝 `agent-ops-manager.md`。手邊有一份你（或課程）實際在用的 agent 清單。

---

## 練習 1：登錄與風險分級（L3）

1. 給 Agent 你的 3–5 個 agent 清單（名稱 + 一句話用途）。
2. 要求它產出登錄表：每個 agent 的擁有者（先留空讓你填）、風險分級、
   建議的核准工具清單、需要真人核准的動作。
3. 討論：哪一個 agent 風險最高？為什麼——是因為它能對外送出、能碰錢、還是能刪東西？

**評分要點**
- ✅ 風險分級依「可觸及的副作用」而非「用得多不多」
- ❌ 全部標「低風險」或不分級

---

## 練習 2：最小權限矩陣（L3）

1. 給情境：一個「週報彙整 agent」，需要讀取專案資料、寫出一份 Markdown 檔。
2. 要求 Agent 產出權限矩陣，預設全部為禁止，只開啟真正需要的格子，每格附理由。
3. 追問：它需要「執行指令」權限嗎？「對外送出」呢？如果不需要，為什麼有人會想先開著？

**評分要點**：學員能說出「預設零權限、逐項開啟」與「先全開再收」的差別與風險。

---

## 練習 3：事故回滾演練（L3→L4）

1. 給情境：某 agent 昨天起把錯誤的折扣碼寫進了對外電子報草稿。
2. 要求 Agent 產出處理程序：偵測 → 止血（凍結＋回滾）→ 用稽核軌跡列出影響範圍 →
   補救 → 無指責根因分析 → 把修正回饋進上線關卡。
3. 要求它指出「如果當初稽核軌跡沒記哪些欄位，這次就查不出影響範圍」。

**評分要點**：學員理解回滾方式與稽核軌跡必須在上線前就備好，事故檢討對事不對人。

---

## 繳交

- 練習 1 的 agent 登錄表（含風險分級與理由）
- 練習 2 的最小權限矩陣（含每格理由）
- 練習 3 的事故處理程序 + 100 字內反思：
  你用過的 AI 工具裡，有哪一個你其實不知道「它做過什麼、影響了什麼」？
