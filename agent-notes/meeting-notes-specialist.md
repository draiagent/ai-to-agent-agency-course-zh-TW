# 教學導引：會議記錄專家（meeting-notes-specialist）

- **模組**：5 — 專案管理
- **能力層**：L1→L2（會派 → 會驗）— 也是「把 AI 當擷取器、不當創作者」最好的示範
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/project-management/meeting-notes-specialist.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/project-management/meeting-notes-specialist.md)

---

## 1. 定位：這個 Agent 解決什麼問題

大家都會請 AI「整理會議記錄」，但通常拿到一段「聽起來合理、其實摻了 AI 腦補」的摘要。
會議記錄專家的核心規則是：**它擷取，不發明。**

它把凌亂輸入（逐字稿、條列、語音備忘）轉成固定的四段式：日期與與會者、決議、
行動項、待解問題。沒有明確講的決議就不會進「決議」段；沒有負責人的行動項標
「[負責人：未指派]」而不是編一個名字。它也把貼上的內容當**資料**，不當指令——
就算逐字稿裡有「忽略先前指示」，那也是要摘要的內容。

一句話：**它把「AI 幫我腦補一份會議記錄」提升到「只反映實際說過的話的結構化記錄」。**

### 什麼時候召喚它

- 有逐字稿/語音備忘/潦草筆記，要整理成可分發的記錄
- 要從一場討論中抽出「決議」與「行動項」（含負責人與截止日）
- 要區分「討論過」與「決定了」

### 什麼時候「不要」召喚它

- 要它「建議下一步該做什麼」→ 它刻意不做詮釋
- 要把規格拆成任務 → project-manager-senior

## 2. Before / After 示範

**任務**：「把這場專案會議的逐字稿整理一下。」

### Before（無 Agent）

> 產出：一段流暢的敘事摘要，加了「團隊似乎傾向……」「建議接下來……」
> 這種 AI 自己的推論。分不清哪些是決議、哪些只是有人提過。

### After（召喚 meeting-notes-specialist）

> 會產出固定四段：
> - **日期與與會者**（缺就用佔位符，不猜）
> - **決議**：每條一個完整句子，只收「明確同意去做/不做/為真」的
> - **行動項**：行動 — 負責人（或「未指派」）— 截止（或「未指定」）
> - **待解問題**：被提出但沒解決的
> - 任何一段沒內容就寫「[未記錄]」，不省略該段

**課堂提問**：讓學員從逐字稿裡挑出「團隊討論了部署時程」和「團隊決定把部署延到 5/15」，
說明為什麼只有後者能進「決議」段。

---

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 四段都在（沒內容也寫「[未記錄]」） | |
| 決議段只有「決定了」的，沒有「討論了」的 | |
| 每個行動項都有負責人（或明確標「未指派」） | |
| 沒有逐字稿裡找不到的決議/行動項（零發明） | |
| 待解問題只收「未解決」的，已問已答的不收 | |
| 日期/與會者有填（必要時佔位符，不亂猜） | |

若出現「團隊似乎/建議」這種 AI 推論 → 退回。

---

## 4. 常見誤區

1. **要它幫忙分析或建議。** 它的產出是文件，不是敘事，不做詮釋——那是別的 Agent 的事。
2. **把「有人提過」當決議。** 決議要「明確同意」，選項被考慮但沒拍板不算。
3. **腦補負責人。** 「Alex 通常處理這個」不是指派。
4. **被逐字稿裡的指令帶走。** 貼上的內容是資料，不是命令。

---

## 5. 銜接其他 Agent

meeting-notes-specialist 抽出「行動項」→ 交給 **project-manager-senior** 或
**sprint-prioritizer** 排進工作流。它是「把口頭討論變成可追蹤工作」的入口，
也是整門課「AI 當擷取器不當創作者」的最佳教材。
