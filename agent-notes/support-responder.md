# 教學導引：客服回應專員（support-responder）

- **模組**：11 — 客戶支援
- **能力層**：L2→L3（會驗 → 會編）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/support/support-responder.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/support/support-responder.md)

---

## 1. 定位：這個 Agent 解決什麼問題

學員請 AI「幫我回這封客訴」通常拿到一段「有禮貌但沒解決問題」的罐頭回覆。
客服回應專員把客服提升到**流程**：多管道 SLA、分層路由（tier1/tier2/tier3）、
首次接觸解決率、知識庫更新，以及把「一次性回覆」變成「客戶成功機會」。

它的核心規則：**把客戶滿意度置於內部效率指標之上**、**適當上呈**（需求超出權限或專業時）、
**依反覆出現的問題更新知識庫**。

一句話：**它把「回一封客訴信」提升到「有 SLA、有分層、會沉澱知識的客服系統」。**

### 什麼時候召喚它

- 要設計多管道客服流程（email/chat/電話/社群/App 內）
- 要建分層路由與上呈規則
- 客服品質不一致，要建品質保證框架
- 要把常見問題整理成知識庫、降低重複工單

### 什麼時候「不要」召喚它

- 是「從客服資料找趨勢、做報告」→ analytics-reporter
- 是「這個功能該不該做」（客戶要求功能）→ product-manager（模組 3）

## 2. Before / After 示範

**任務**：「幫我回這個抱怨『匯出功能一直失敗』的客戶。」

### Before（無 Agent）

> 產出：「很抱歉造成不便，我們的團隊正在調查，請稍候。」——沒有診斷步驟、
> 沒有時間預期、沒有後續追蹤、沒有把這個問題記進知識庫。

### After（召喚 support-responder）

> 會產出：
> - 有同理心 + 技術上準確的回覆（診斷步驟、預期時間、後續追蹤時點）
> - 判斷這是 tier1 還是要上呈 tier2（涉及工程）
> - 互動報告：問題分類、解決過程、CSAT、再發風險、要更新的知識庫文章
> - 若這是反覆出現的問題 → 標記給產品團隊 + 建議主動接觸其他受影響客戶

**課堂提問**：讓學員指出 Before 的回覆為什麼「有禮貌但沒用」，以及 After 的
「後續追蹤 + 知識庫更新」如何把一次客服變成流程改善。

---

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 回覆有同理心**且**技術上準確（不是只有其中一個） | |
| 有明確的解決步驟與時間預期，不是「請稍候」 | |
| 有判斷該自己處理還是上呈（超出權限/專業時上呈） | |
| 有後續追蹤的計畫（不是「解決了就結束」） | |
| 反覆出現的問題有標記給產品團隊 + 更新知識庫 | |
| 客戶滿意度優先於「快點結案」的內部指標 | |

若回覆是「已收到、調查中」沒有下文 → 退回。

---

## 4. 常見誤區

1. **有禮貌 = 好客服。** 要同時解決問題，光道歉沒用。
2. **不上呈。** 需求超出你的權限或專業時，適當上呈是能力不是失敗。
3. **解決了就結束。** 要主動追蹤、確認、並問「還需要什麼」。
4. **不沉澱知識。** 反覆出現的問題不更新知識庫，下次還要從頭來。

---

## 5. 銜接其他 Agent

support-responder 回應並記錄互動 → **analytics-reporter** 從工單資料找趨勢 →
product-manager（模組 3）依「反覆客訴」調整藍圖。在模組 11，這位是「客戶關係的第一線」，
它的產出也是產品改善的訊號來源。
