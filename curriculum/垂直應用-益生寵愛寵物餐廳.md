# 垂直應用模組：以益生寵愛寵物餐廳為例 — 用 Agent 團隊做 O2O 與 OEM 雙軌經營

> **模組定位**：這是一個**整合模組**，不教新角色，而是把前面學過的數位員工，
> 依一個真實中小企業情境編成一支跨部門團隊。適合放在課程中後段（學員已修過模組 1
> 與至少 3 個部門模組之後）。
>
> **情境來源**：EMBA 論文《寵物餐廳創新經營策略：以益生寵愛寵物餐廳為例》的四主軸分析框架。
> 本模組只借用其**分析結構與訪談角色設定**作為教學骨架，不代表該個案的實際經營決策。
>
> **搭配檔案**：姊妹 repo 的
> [`rosters/益生寵愛-寵物餐廳-O2O與OEM團隊.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/rosters/益生寵愛-寵物餐廳-O2O與OEM團隊.md)
> 是「團隊名單配方」；本檔是「怎麼教 + 練習」。

---

## 學習目標

修畢本模組，學員能：

1. 把一個模糊的經營課題（「餐廳想多角化」）拆成**四個有順序的主軸**，每段指派對的數位員工。
2. 示範 **L3「會編」**：把 4–6 個 Agent 串成一段有交付物的流程。
3. 示範 **L2「會驗」** 在跨部門情境的難處：一個主軸的產出是下一個主軸的輸入，驗收不能只看單點。
4. 說明「非人類利害關係人」（毛孩）為什麼需要一個專屬代言角色。

---

## 一頁背景（發給學員）

**個案**：一家中小型寵物餐廳，資源有限。想在「開店」之外長出可持續商業模式。

**核心命題**：從資源限制出發 → 用**資源整合**與**價值共創**累積顧客信任 →
再用**線上線下整合**延伸出 **B2C 電商** 與 **B2B OEM/ODM** 並行的**商業模式創新**。

| 主軸 | 理論 | 一句話 |
|---|---|---|
| 一、資源整合 | RBV（Barney, 1991） | 先盤點稀缺資源，決定不做什麼 |
| 二、價值共創 | S-D Logic（Vargo & Lusch, 2004） | 顧客／毛孩／員工／醫師／產學一起創造價值 |
| 三、線上線下整合 | Berry, 1983；Pine & Gilmore, 1998 | 把到店體驗接上線上回購 |
| 四、商業模式創新 | Teece, 2010 | B2C 電商與 B2B 代工兩條營收線並行 |

**訪談角色**（練習時當「資料來源」用）：A1 空間設計師、B1／B2 店長店員、C1 品牌合作醫師、
D1／E1 產學研發與品管、F1 OEM/ODM 客戶、G1–G3 飼主。

## 四堂課的結構

每堂 90 分鐘，帶一個主軸。

### 第 1 堂：資源整合（會派 + 會驗）

**團隊**：business-strategist、financial-analyst、ux-researcher、ui-designer

**流程**：
1. 給 business-strategist 一份「這家店有什麼」的粗清單，要它做 VRIN 盤點、收斂成 2–3 個聚焦選擇。
2. 給 financial-analyst 這 2–3 個選擇，要它各附單位經濟與現金流上限、情境與敏感度。
3. ux-researcher 設計一份對 G1–G3 飼主與 B1／B2 店員的訪談大綱，目的是驗證「顧客重視的、
   我們剛好有」的資源是否真的存在。
4. ui-designer 針對「店內空間體驗」提出設計方向（動線、毛孩友善、可拍照）。

**驗收練習**：學員拿到 business-strategist 的產出，要指出哪幾項「不是 VRIN，只是常見做法」並退回。

### 第 2 堂：價值共創（會驗 + 非人類利害關係人）

**團隊**：animal-welfare-advocate、clinical-evidence-agent、ux-researcher、support-responder、content-creator

**流程**：
1. animal-welfare-advocate 做一份「用餐情境毛孩壓力源盤點」+ 訊號翻譯對照表。
2. clinical-evidence-agent 針對「醫師背書的鮮食營養主張」列出必須有的證據與界線。
3. content-creator 把共創故事寫成有受眾與支柱的內容草案。
4. support-responder 設計一個「飼主回饋 → 流程改善項」的迴路模板。

**驗收練習**：給一句行銷文案「毛孩超愛，吃到盤底朝天！」，讓 animal-welfare-advocate 審查——
它應該要求用行為與生理證據替換「可愛化描述」，必要時行使福利否決權。

### 第 3 堂：線上線下整合（會編）

**團隊**：growth-hacker、ecommerce-operator、analytics-reporter、seo-specialist、ppc-strategist

**流程**：
1. growth-hacker 把「到店 → 加 LINE／社群 → 線上回購」畫成漏斗，每步一個可證偽實驗。
2. ecommerce-operator 設計會員分級與第 7／21／30 天回購劇本，把線下客導進去。
3. seo-specialist + ppc-strategist 各出一版「在地客怎麼找到我們／被我們找到」。
4. analytics-reporter 定義 O2O 儀表板指標（世代留存、線下→線上轉換、回購率）。

**編排練習**：學員把上面 4 份產出接成**一條流程圖**，標出每個交接點的輸入與輸出，
並指出「哪一步的產出如果爛掉，會讓後面全錯」。

### 第 4 堂：商業模式創新（會編 + 會養）

**團隊**：business-strategist、pricing-analyst、deal-strategist、ecommerce-operator、bookkeeper-controller、esg-sustainability-officer

**流程**：
1. business-strategist 設計 B2C／B2B 雙軌模式：各自的價值主張、共用與分離的資源。
2. pricing-analyst 出 B2C 會員分級（附算式）+ B2B OEM/ODM 量價階梯與底價（附 ±20% 敏感度）。
3. deal-strategist 對 F1 代工客戶做 MEDDPICC 評分，找缺口。
4. bookkeeper-controller 設計兩條營收線的帳務分離與成本歸屬。
5. esg-sustainability-officer 準備「若 F1 要求供應鏈永續揭露」的最小可信版本。

**會養練習**：跑完一輪後，學員修改其中一個 Agent 的設定（例如給 pricing-analyst
補「寵物鮮食冷鏈成本結構」的背景），再跑一次，比較產出差異——這就是 L4。

## 期末整合作業

學員扮演「店主」，用四個主軸的順序，把四堂課的產出串成一份
**《益生寵愛雙軌經營計畫》草案**（8–12 頁），並在每一步旁邊註明：

- 這一步我召喚了誰、為什麼
- 我驗收時退回了什麼、要求補什麼
- 這一步的產出，是下一步哪個人的輸入

**評分要點**：
- ✅ 四個主軸有順序、有交接、每個交接點看得出輸入輸出
- ✅ 至少一處明確的「驗收退回」紀錄
- ✅ 毛孩福利有被 animal-welfare-advocate 這條線顧到
- ❌ 把四個主軸各自獨立寫成四份報告，之間沒有接點

## 常見誤區

1. **把整合模組當成「多找幾個 Agent 一起做」。** 重點是**順序與交接**，不是人多。
2. **跳過驗收直接串。** 第一個主軸的資源盤點若沒驗收，後面三個主軸都建在流沙上。
3. **忘記毛孩。** 沒有 animal-welfare-advocate 這條線，價值共創就少了沉默的一方。
4. **B2C 與 B2B 用同一組數字。** 兩條營收線的單位經濟、底價、客戶邏輯完全不同。
