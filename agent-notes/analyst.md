# 教學導引：GIS 分析師（analyst）

- **模組**：16 — GIS（地理資訊系統）
- **能力層**：L1→L2（會派 → 會驗）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/gis/analyst.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/gis/analyst.md)

> 這個模組是「垂直領域示範」——證明連 GIS 這種專門領域，也能用「規格化角色」的方式
> 把日常操作交給 Agent，且驗收原則不變。

---

## 1. 定位：這個 Agent 解決什麼問題

GIS 分析師是 GIS 部門的主力——製作地圖、管理圖層、執行空間查詢、維護資料完整性。
它抓別人漏掉的東西：**沒對齊的座標系統（CRS）、缺失的屬性、孤立的圖層**。

它的核心規則：**任何操作前先驗證 CRS**（GIS 錯誤的頭號來源）、**絕不假設資料是乾淨的**
（分析前先檢視）、**記錄來源**（每個圖層要有來源履歷）、**了解你的受眾**
（高階地圖簡單醒目、技術地圖詳細有註解）。

一句話：**它把「幫我做張地圖」提升到「CRS 一致、資料驗證過、有來源履歷、對受眾有效的地圖」。**

### 什麼時候召喚它

- 要製作可出版的地圖（報告/簡報/Web）
- 要載入、檢視、驗證多來源空間資料
- 要做基本地理處理（緩衝區、裁剪、融合、相交、聯集）
- 要做空間查詢（依位置/屬性/空間關係選取）

### 什麼時候「不要」召喚它（Agent 定義自己列的）

- 需要策略性架構 → Technical Consultant
- 需要複雜統計分析 → Spatial Data Scientist
- 需要自動化 ETL 管線 → Spatial Data Engineer

## 2. Before / After 示範

**任務**：「幫我把這兩份資料做成一張地圖。」

### Before（無 Agent）

> 產出：直接疊圖、上色、匯出。兩份資料的座標系統不一樣，圖層對不齊；
> 顏色用了紅綠（色盲不友善）；沒記錄資料來源。

### After（召喚 GIS 分析師）

> 會依流程走：
> 1. 載入並檢視（CRS、屬性、幾何檢查）
> 2. 確認所有圖層在同一個座標系統
> 3. 執行操作（查詢/分析/符號化，用 ColorBrewer 方案、避開紅綠）
> 4. 建立產出（含圖例、比例尺、指北針、中繼資料）
> 5. 品質檢查：產出有回答原始問題嗎？
> 6. 附簡短文件交付（含資料來源履歷）

**課堂提問**：讓學員理解「為什麼 CRS 不一致是 GIS 錯誤的頭號來源」。

---

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 有先驗證所有圖層的 CRS 一致 | |
| 分析前有檢視資料（屬性、幾何、空值、重複） | |
| 每個圖層有來源履歷（從哪來、何時、做過什麼轉換） | |
| 符號化依受眾（高階簡單 / 技術詳細）、避開紅綠 | |
| 地圖有圖例、比例尺、指北針、中繼資料 | |
| 產出有回答「原始問題」 | |

若地圖漂亮但 CRS 沒驗、來源沒記 → 退回。

---

## 4. 常見誤區

1. **假設資料乾淨。** 分析前一律跑一遍檢視。
2. **忽略 CRS。** 座標系統不一致，疊圖就對不齊。
3. **用紅綠配色做關鍵分類。** 色盲不友善，用 ColorBrewer。
4. **地圖好看 = 溝通有效。** 要問「這張圖回答了什麼問題」。

## 5. 銜接其他 Agent

GIS 分析師產出的地圖與空間查詢結果，可餵給 analytics-reporter（模組 11）做報告、
餵給 business-strategist（模組 18）做選址/市場分析。在模組 16，這位示範「垂直領域的
日常操作也能 Agent 化」——驗收原則（先驗證、記來源、對受眾有效）跟其他模組完全一致。
