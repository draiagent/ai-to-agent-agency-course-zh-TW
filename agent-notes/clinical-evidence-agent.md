# 教學導引：臨床證據 Agent（clinical-evidence-agent）

- **模組**：14 — 醫療
- **能力層**：L2→L4（會驗 → 會養）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/healthcare/clinical-evidence-agent.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/healthcare/clinical-evidence-agent.md)

---

## 1. 定位：這個 Agent 解決什麼問題

醫療新創要做臨床主張，但很容易越界成「診斷權威」，或用沒有出處的主張自砸招牌。
臨床證據 Agent 是一個**證據框架**（不是診斷工具），維護每一份對外輸出的臨床證據完整性。

它的核心規則：**絕不做沒有資料出處的結果主張**（沒出處的主張比沒主張更糟）、
**臨床 AI 只做決策支援，絕不宣稱診斷權威**、**先為最嚴格的受眾（同儕審查）撰寫**、
**明確區分已驗證 / 方向性 / 未驗證主張**。

一句話：**它把「聽起來很強的臨床宣稱」提升到「每個主張都有出處或被標記、不越診斷權威界線」。**

### 什麼時候召喚它

- 要為投資人材料/法規申報/產品描述做臨床證據審查
- 要稽核既有文件的「已驗證 vs 未驗證」主張
- 要框定臨床 AI 的定位（決策支援，非診斷）
- 要為不同受眾（同儕審查/投資人/監管/醫師/病人）調整框定

### 什麼時候「不要」召喚它

- 要它做臨床決策或醫療建議 → 它明確不做
- 是一般的證據綜整（非醫療）→ synthesist（模組 12）

## 2. Before / After 示範

**任務**：「幫我寫一段投資人簡報，講我們的 AI 分診工具的臨床成效。」

### Before（無 Agent）

> 產出：「我們的 AI 診斷準確率達 94%，大幅優於人類醫師……」——
> 沒有出處、把「決策支援」寫成「診斷」、把內部試點數字當成已驗證發現。

### After（召喚 clinical-evidence-agent）

> 會產出：
> - 每個結果主張都附出處或標記；把「94%」歸類為已驗證/方向性/未驗證
> - 框定為「這個工具讓醫師更快取得他們早已知道如何使用的證據，不是臨床判斷的替代品」
> - 方向性外推放進獨立的「前瞻性」段落，不跟已驗證發現放同一句
> - 用詞：「醫師」，不用「臨床人員」「醫療提供者」
> - 若某主張未經持照醫師審查 → 交付前標記

**課堂提問**：讓學員理解「診斷權威界線」——為什麼越過一次就永久定義法規曝險。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 每個結果主張都有出處，或明確被標記為未驗證 | |
| 已驗證 / 方向性 / 未驗證主張有分類，方向性有加限定詞 | |
| 臨床 AI 被框定為「決策支援」，沒有「AI 診斷/AI 治療建議」的說法 | |
| 同一份文件不混用受眾框定（同儕審查版 vs 投資人版分開） | |
| 未驗證預測不跟已驗證發現放同一句 | |
| 用詞是「醫師」，不是「臨床人員/醫療提供者」 | |

若出現「保證診斷準確」「AI 取代醫師」的說法 → 退回。

---

## 4. 常見誤區

1. **沒出處的主張。** 在醫療中，沒出處的主張比沒主張更糟。
2. **把「決策支援」講成「診斷」。** 這條界線不可談判。
3. **先為投資人寫、再改給同儕審查。** 反過來：過得了同儕審查就過得了投資人。
4. **把方向性外推當已驗證發現。** 要用「我們的營運資料顯示……」這種限定詞。

## 5. 銜接其他 Agent

clinical-evidence-agent 為醫療輸出把關 → 與 synthesist（模組 12）互補（一個管醫療合規、
一個管一般文獻）、與 financial-analyst（模組 7）合作做投資人材料。在模組 14，
這位示範「高度受監管領域的 Agent，關鍵規則就是『不越界』」——這是 L4「會養、能治理」
在合規面的體現。
