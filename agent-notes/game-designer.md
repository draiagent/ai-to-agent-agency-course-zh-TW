# 教學導引：遊戲設計師（game-designer）

- **模組**：15 — 遊戲開發
- **能力層**：L2→L3（會驗 → 會編）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/game-development/game-designer.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/game-development/game-designer.md)

---

## 1. 定位：這個 Agent 解決什麼問題

學員請 AI「幫我設計一個遊戲機制」通常拿到一段「聽起來好玩、但工程師做不出來」的描述。
遊戲設計師把創意願景轉譯成**有文件、可實作**的設計——GDD、遊戲循環、經濟平衡、
玩家進程。

它的核心規則：**每個機制都要記錄目的、玩家體驗目標、輸入、輸出、邊界案例、失敗狀態**、
**每個經濟變數都要有理由（不要魔術數字）**、**從玩家動機往外設計，不從功能清單往內設計**、
**所有數值一開始都是假設，標 `[PLACEHOLDER]` 直到實測**。

一句話：**它把「一個好玩的點子」提升到「有 GDD、有調校試算表、可實作可實測的系統」。**

### 什麼時候召喚它

- 要設計玩法系統、機制、經濟、玩家進程並寫成 GDD
- 要設計核心遊戲循環（分秒/單場/長期鉤子）
- 要用資料平衡經濟與進程曲線
- 要設計上手引導流程

### 什麼時候「不要」召喚它

- 是故事、對話、世界觀 → narrative-designer
- 是非遊戲的行為經濟學應用（例：App 留存）→ growth-hacker（模組 4）借用同樣的心理學

## 2. Before / After 示範

**任務**：「幫我設計一個資源採集機制。」

### Before（無 Agent）

> 產出：「玩家點擊資源點就能採集，採集需要 5 秒，給 10 個資源。」——
> 5 秒和 10 個哪來的？玩家在做什麼決定？失敗會怎樣？經濟會不會爆？

### After（召喚 game-designer）

> 會產出：
> - 機制規格：目的、玩家幻想、輸入、輸出、成功條件、失敗狀態、邊界案例、調校槓桿、相依
> - 所有數值標 `[PLACEHOLDER]`，附「在等級 5 測試」這類調校備註
> - 經濟平衡試算表（用公式不用寫死值）+ 「壞掉」的定義
> - 核心循環文件：這個機制在分秒/單場/長期循環中的位置

**課堂提問**：讓學員指出 Before 的「5 秒 / 10 個」為什麼是魔術數字，以及
「玩家在做什麼決定」為什麼是設計的核心問題。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 每個機制都有完整規格（目的/玩家體驗/輸入/輸出/邊界案例/失敗狀態） | |
| 每個數值都有理由或標 `[PLACEHOLDER]` + 調校備註，沒有魔術數字 | |
| 設計回答「玩家感受到什麼？在做什麼決定？」 | |
| 有經濟平衡試算表（公式，不是寫死值）+ 「壞掉」的定義 | |
| 沒有「不帶來有意義選擇」的複雜度 | |
| 核心循環有分秒/單場/長期三層 | |

若機制描述沒有「失敗狀態」與「玩家決定」→ 退回。

---

## 4. 常見誤區

1. **把它當 code generator。** 它的交付物是「設計 + GDD + 調校試算表」。
2. **魔術數字。** 每個成本/報酬/冷卻都要有理由，或標 PLACEHOLDER 待實測。
3. **從功能清單往內設計。** 要從玩家動機往外。
4. **加複雜度不加選擇。** 不帶來有意義決策的系統該移除。

## 5. 銜接其他 Agent

game-designer 設計系統與經濟 → **narrative-designer** 讓敘事與玩法不可分割 →
psychologist（模組 13）提供玩家動機的心理框架。game-designer 的「行為經濟學」
（損失趨避、變動獎勵）也跟 growth-hacker（模組 4）共用同一套心理學。
在模組 15，這位負責「把好玩變成可實作、可實測」。
