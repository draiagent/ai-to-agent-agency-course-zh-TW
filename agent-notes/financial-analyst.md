## 1. 定位：這個 Agent 解決什麼問題

學員請 AI「幫我做個財務預測」通常拿到一張看起來很專業、但**假設藏起來、只有單一數字**
的試算表。財務分析師（人設「Morgan」）的核心規則是：**先陳述假設，再給結論**、
**一律建立情境分析**（基準/樂觀/悲觀）、**每個建議都做敏感度測試**。

它的名言是「營收是虛榮，利潤是理智，但現金流才是現實」。它把「一個漂亮的數字」
提升到「假設可被挑戰、範圍可被看見的決策支援」。

一句話：**它把「一張預測試算表」提升到「假設明確、有情境、可稽核的財務分析」。**

### 什麼時候召喚它

- 要做財務模型、預測、估值（DCF、可比較分析）
- 要做投資決策的商業論證（NPV/IRR/回本期）
- 要做差異分析（預算 vs 實際）與根因分解
- 要把複雜財務數字翻譯成非財務主管能行動的敘事

### 什麼時候「不要」召喚它

- 是日常記帳、月結、對帳 → bookkeeper-controller
- 是「這個市場的商業模式該長怎樣」→ business-strategist

## 2. Before / After 示範

**任務**：「幫我預測明年的營收與現金流。」

### Before（無 Agent）

> 產出：一張「營收成長 20%」的三年預測，一個數字。沒說 20% 從哪來、
> 若掉到 12% 會怎樣、現金流何時轉正。

### After（召喚 financial-analyst）

> 會產出：
> - **關鍵假設表**：每個假設的基準/樂觀/悲觀值 + 來源
> - 三表摘要（損益、現金流），標清楚哪些是歷史、哪些是預測
> - 敏感度分析（營收成長 ±5% × 利潤率 ±2% 的 FCF 矩陣）
> - 「以」開場的結論：「若成長掉到 12%，我們 Q4 會違反債務契約條款」

**課堂提問**：讓學員指出「Before 的單一數字為什麼不能拿來做決策」，以及
「敏感度分析」揭露了什麼 Before 藏起來的風險。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 假設在結論**之前**明確列出，且每個有來源 | |
| 有情境分析（基準/樂觀/悲觀），不是單點預測 | |
| 歷史資料與預測清楚分開標示 | |
| 有敏感度測試：關鍵假設變動時結論會不會翻轉？ | |
| 效果量用有意義的單位（美元、天數、百分點），不是「很大的機會」 | |
| 有誠實的壞消息（若市場在萎縮就說） | |

若只有一個數字、假設藏在公式裡 → 退回。

---

## 4. 常見誤區

1. **把「數字不會說謊」當真。** 數字可以被排列來說任何故事；要找底下的真相。
2. **單點預測。** 未來不確定，要給範圍與驅動因子。
3. **精確度 ≠ 準確度。** 粗估上不要放四位小數，那是虛假信心。
4. **為自己建模。** 模型要可稽核、有文件，讓沒建它的人也能用。

## 5. 銜接其他 Agent

ux-researcher/product-manager 提供業務假設 → **financial-analyst 建模並量化風險** →
決策者拍板。它的敏感度分析也會告訴 sprint-prioritizer「哪個功能的財務影響最大」。
在模組 7，這位是「把商業判斷變成有數字撐腰的決策」的那一棒。
