# 教學導引：分析報告專員（analytics-reporter）

- **模組**：11 — 客戶支援
- **能力層**：L2（會驗）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/support/analytics-reporter.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/support/analytics-reporter.md)

---

## 1. 定位：這個 Agent 解決什麼問題

學員請 AI「幫我分析這些資料」通常拿到一堆圖表、但沒有「所以呢」。分析報告專員的
核心規則是：**把所有分析連到業務成果與可行動洞見**、**優先做「驅動決策」的分析而非探索性研究**、
**分析前驗證資料的準確與完整**、**對所有結論做統計顯著性檢定**。

它把「一堆圖」提升到「有基準、有信心水準、有具體建議與負責人的報告」。它跟
statistician（模組 13）互補：statistician 管方法論嚴謹度，analytics-reporter 管
「把嚴謹分析變成主管能用的儀表板與敘事」。

一句話：**它把「資料視覺化」提升到「數據驅動的決策支援」。**

### 什麼時候召喚它

- 要建含即時指標與 KPI 追蹤的儀表板
- 要做客戶分析（世代分析、分群、生命週期價值）
- 要做差異分析、A/B 測試分析、行銷歸因
- 要把複雜資料翻譯成非技術主管能行動的敘事

### 什麼時候「不要」召喚它

- 是研究設計、因果推論的嚴謹度問題 → statistician
- 是財務建模與估值 → financial-analyst（模組 7）

## 2. Before / After 示範

**任務**：「幫我分析這三個月的客服工單資料。」

### Before（無 Agent）

> 產出：一堆長條圖、圓餅圖。「工單量在增加」「滿意度還可以」。
> 沒說信心水準、沒有基準、沒有「該做什麼」。

### After（召喚 analytics-reporter）

> 會產出：
> - 執行摘要：主要洞見（附量化影響）、統計信心、業務影響
> - 需立即採取的行動（高/中/長期，每條附影響、工作量、成功指標）
> - 資料基礎：來源、樣本數、時間範圍、資料品質分數
> - 關鍵發現：目前績效 vs 基準、績效驅動因子、改善機會
> - RFM/世代分析（若適用）

**課堂提問**：讓學員指出「Before 的圖表為什麼無法拿來做決策」（提示：沒有基準、沒有建議、沒有信心）。

---

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 每個洞見都連到一個業務成果與可行動建議 | |
| 有基準（改善前的數字），不是只有「現在的狀態」 | |
| 有統計顯著性/信心水準，不是「感覺有差」 | |
| 建議是具體動作 + 影響 + 成功指標，不是「要更好」 | |
| 有陳述資料品質（完整性、準確性），分析前有驗證 | |
| 分析是「驅動決策」導向，不是「探索看看」 | |

若報告只有圖、沒有「所以呢」→ 退回。

---

## 4. 常見誤區

1. **圖表當洞見。** 圖是呈現，洞見是「這意味著什麼、該做什麼」。
2. **沒有基準就宣稱改善。** 「留存 58%」要對照「上季 52%」才有意義。
3. **相關當因果。** 用了某功能的使用者留存較好，可能是他們本來就更投入。
4. **精確度 ≠ 準確度。** 資料髒的話，四位小數只是虛假信心。

## 5. 銜接其他 Agent

support-responder 產生工單資料 → **analytics-reporter 找趨勢、做報告** →
product-manager（模組 3）依洞見調整藍圖、growth-hacker（模組 4）設計實驗。
statistician（模組 13）則負責把關「這個結論的方法論站不站得住」。
