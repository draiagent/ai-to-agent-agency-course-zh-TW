# 教學導引：敘事設計師（narrative-designer）

- **模組**：15 — 遊戲開發
- **能力層**：L2→L3（會驗 → 會編）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/game-development/narrative-designer.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/game-development/narrative-designer.md)

---

## 1. 定位：這個 Agent 解決什麼問題

game-designer 管系統與經濟；敘事設計師管**故事系統**——它理解遊戲敘事不是
「插在玩法之間的電影劇本」，而是選擇、後果與世界一致性組成的設計系統。

它的核心規則：**每一句台詞都要通過「真人會這樣說嗎？」測試**（不要偽裝成對話的資訊傾倒）、
**選擇必須在「種類」上不同，不只在「程度」上**、**世界觀設定永遠是選配**（關鍵路徑
不看收集品也能懂）、**每個重大故事節拍都要連到一個玩法後果**。

一句話：**它把「一段對話腳本」提升到「分支有重量、世界有一致性、敘事與玩法互相強化的系統」。**

### 什麼時候召喚它

- 要設計分支對話、故事結構、角色語氣
- 要建世界觀設定架構（表層/投入/深層三層）
- 要設計環境敘事（用道具與空間說故事）
- 要讓敘事選擇與玩法選擇對齊

### 什麼時候「不要」召喚它

- 是系統、機制、經濟 → game-designer
- 是角色的心理框架 → psychologist（模組 13，可協作）

## 2. Before / After 示範

**任務**：「幫我寫一段玩家初次見到指揮官的對話。」

### Before（無 Agent）

> 產出：一段流暢但「像編劇不像角色」的對話，角色互相解釋他們早就知道的背景，
> 玩家的選項是「我會幫你」vs「我晚點幫你」——程度不同、種類相同。

### After（召喚 narrative-designer）

> 會產出：
> - 引擎可用格式（Ink/Yarn）的對話節點，附場景/語氣註解
> - 選項在**種類**上不同（務實 / 挑釁 / 觀察），每個導向不同的角色反應
> - 角色語氣支柱：詞彙、句子節奏、迴避的話題、口頭習慣、潛台詞預設
> - 每則對話節點有清楚的戲劇功能（揭露 / 建立關係 / 製造壓力 / 交付後果）

**課堂提問**：讓學員區分「我會幫你」vs「我晚點幫你」（不是有意義的選擇）
和「務實 / 挑釁 / 沉默」（種類不同、導向不同關係）。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 每句台詞通過「真人會這樣說嗎？」——沒有偽裝成對話的資訊傾倒 | |
| 沒有「你也知道」式對話（角色互相解釋早知道的事） | |
| 選擇在種類上不同，不只程度不同 | |
| 分支會匯合而不勉強；死路有明確設計正當性 | |
| 世界觀設定是選配——關鍵路徑不看收集品也能懂 | |
| 每個重大故事節拍連到一個玩法後果 | |

若選項是「同一件事的兩種程度」、或角色在對玩家講解背景 → 退回。

---

## 4. 常見誤區

1. **對話聽起來像編劇。** 每句要像那個角色，有一致的語氣支柱。
2. **「你也知道」式對話。** 角色不會為了玩家的利益向彼此解釋已知的事。
3. **假選擇當真選擇。** 「幫你」vs「晚點幫你」不是有意義的選擇。
4. **敘事選擇多於玩法選擇。** 不要在沒有機制選擇的遊戲裡給一堆敘事分支。

---

## 5. 銜接其他 Agent

game-designer（系統）↔ **narrative-designer（故事系統）** 必須互相強化——每個故事節拍
連到玩法後果。psychologist（模組 13）提供角色心理框架，narrative-designer 據以寫
一致的對話與分支。在模組 15，這兩位合起來就是「敘事與玩法不可分割」的示範。
