# 教學導引：營運持續規劃師（business-continuity-planner）

- **模組**：18 — 跨域專業
- **能力層**：L2→L3（會驗 → 會編）
- **對應 Agent 定義**：[`AI-to-Agent-Agency-zh-TW` / `agents/specialized/business-continuity-planner.md`](https://github.com/draiagent/AI-to-Agent-Agency-zh-TW/blob/main/agents/specialized/business-continuity-planner.md)（🆕 本 repo 原創，非上游衍生）

---

## 1. 定位：這個 Agent 解決什麼問題

`security/` 的角色處理「有人攻擊你」。這個角色處理**其他所有讓營運停擺的事**：
停電、天災、主要供應商倒閉、關鍵員工驟然離職、機房或倉庫不能用、傳染病造成人力短缺。

營運持續規劃師負責在事發之前，把「哪些流程不能斷、能忍多久、斷了怎麼辦」寫清楚、
演練過，並讓不是作者的人也能照著執行。

它的核心紀律：**從業務衝擊分析（BIA）出發**、**每個關鍵流程有 RTO／RPO 與負責人**、
**沒演練過的計畫不算數**、**單點故障要標出來**、**危機溝通要預先備好發言人與範本**、
**人身安全優先**、**計畫要寫給「當天唯一在場的人」看**。

一句話：**它把「應該不會出事吧」提升到「最痛的三個流程、各能忍多久、斷了誰負責、演練過沒有，都寫在紙上」。**

### 什麼時候召喚它

- 要做業務衝擊分析、訂關鍵流程的 RTO／RPO
- 要盤點單點故障（單一供應商、單一機房、「只有他會」）
- 要寫天災／斷鏈／關鍵人員／基礎設施的情境劇本
- 要設計桌上演練與危機溝通範本

### 什麼時候「不要」召喚它

- 是資安入侵事件的處置 → `security/` 的角色（但本角色會把它當一種營運中斷情境納入劇本）
- 是專案時程風險管理 → `project-manager-senior`
- 是氣候情境的財務影響量化 → `financial-analyst`（與 `esg-sustainability-officer` 的 TCFD 工作）

## 2. Before / After 示範

**任務**：「我們要不要準備一份營運持續計畫？」

### Before（無此角色）

> 產出：一份 20 頁文件，寫「若發生災害，應盡快恢復營運，並通知相關人員」。
> 沒有 BIA、沒有 RTO、沒標單點故障、從沒演練、聯絡方式過期。

### After（召喚 business-continuity-planner）

> 會產出：
> - BIA：列出流程，量化「斷一小時損失多少」，訂最大可容忍中斷期
> - RTO／RPO 登錄：收款 RTO 2 小時、出貨 RTO 1 天，各有負責人
> - 單點故障清單：只有一家金流商、只有一個倉庫、對帳只有一個人會
> - 情境劇本：停電那天，第一步是清點在場人力，接著切換備援、啟用預備公告範本
> - 桌上演練腳本：注入「備援也失效」「媒體來電」，看決策卡在哪
> - 危機溝通樹：預先授權的發言人、對員工／客戶／主管機關的第一則通知範本

**課堂提問**：讓學員找出 Before 那句「盡快恢復」為什麼沒用——「盡快」不是恢復目標。

## 3. 怎麼帶學員「驗收」它的產出

| 檢核點 | 有 / 無 |
|---|---|
| 有業務衝擊分析，且對策是**接在 BIA 之後**，不是憑空開始 | |
| 每個關鍵流程有具體 RTO／RPO（時間，不是「盡快」）與負責人 | |
| 單點故障有清單，且備援不與主線共命運（機房／供應商／人員） | |
| 每個情境劇本第一步都是人身安全 | |
| 危機溝通有預先授權發言人與範本，不是事發當天才寫 | |
| 計畫能被非作者執行：步驟、聯絡方式、權限都在文件裡 | |
| 有演練排程，且演練發現項會追到關閉 | |

若計畫從沒演練過、或沒有 BIA 就直接寫對策 → 退回。

---

## 4. 常見誤區

1. **跳過 BIA 直接買備援。** 不知道哪個流程最痛、能忍多久，備援投資就是亂猜。
2. **「盡快恢復」當目標。** 恢復目標必須是具體時間。
3. **備援跟主線共命運。** 同機房、同供應商、同一個人，都不是真的備援。
4. **計畫寫完就歸檔。** 沒演練過的 BCP 是紙；演練發現項不關閉等於沒演練。
5. **事發當天才想措辭。** 危機溝通範本與發言人要預先定好。

## 5. 銜接其他 Agent

它與 `security/` 的事件處理職能互補（一個管入侵、一個管天災與流程中斷），
與 `esg-sustainability-officer`（氣候實體風險）、`agent-ops-manager`（數位員工中斷
也是一種營運中斷，納入劇本）、`support-responder`（危機期間的客服應對）協作。
在治理層面，`agent-ops-manager` 管數位勞動力的韌性，本角色管實體與流程的韌性。
